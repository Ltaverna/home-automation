# Fase 1 — Base (R2130 + Docker + HA + MQTT + LG webOS) — Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Dejar la reComputer R2130 corriendo Pi OS 64-bit con Docker Compose (Home Assistant + Mosquitto), integrada con la LG OLED C5 y el iPhone de Lucas, con configs versionadas en este repo y backup nocturno.

**Architecture:** Nodo único (R2130) headless, operado por SSH desde el mini-PC. Todo servicio corre como contenedor definido en `docker-compose.yml`; las configs viven en el repo (`git clone` en `/opt/home-automation` de la R2130). Sin compras: solo software + hardware existente.

**Tech Stack:** Raspberry Pi OS Lite 64-bit (Bookworm), Docker + compose plugin, Home Assistant Container, eclipse-mosquitto 2, integración `webostv`, HA Companion (iOS).

**Convención:** los comandos se ejecutan **desde el mini-PC**. Los que deben correr en la R2130 van como `ssh r2130 '<comando>'` (el alias `r2130` se crea en la Task 1). `<R2130_IP>` y `<TV_IP>` se descubren en las Tasks 1 y 8.

### Task 1: Localizar la R2130 en la red y evaluar su OS

**Files:**
- Modify: `~/.ssh/config` (mini-PC)

- [ ] **Step 1: Buscar la R2130 en la LAN**

La R2130 tiene que estar conectada por **Ethernet** al router y encendida.

```bash
# Detectar la subred local
ip -4 route show default
# Escanear (instalar nmap si falta: sudo apt install -y nmap)
sudo nmap -sn $(ip -4 route show default | awk '{print $3}' | sed 's/\.[0-9]*$/.0\/24/') | grep -B2 -iE 'raspberry|seeed|recomputer'
```

Expected: una línea `Nmap scan report for <hostname> (<R2130_IP>)` con MAC vendor `Raspberry Pi` o `Seeed`. Si no aparece: mirar la lista de clientes DHCP en la web del router, o conectar monitor+teclado a la R2130 y correr `hostname -I`.

- [ ] **Step 2: Probar SSH y detectar el OS instalado**

```bash
ssh lucas@<R2130_IP> 'cat /etc/os-release && uname -m && lsblk -o NAME,SIZE,MOUNTPOINT'
# Si "lucas" no existe, probar los usuarios de fábrica: pi, recomputer, seeed
```

Expected (caso bueno): `ID=debian` + `VERSION_CODENAME=bookworm` (o posterior) + `aarch64` + el SSD NVMe montado en `/`. Seeed entrega la R2130 con Raspberry Pi OS Bookworm 64-bit preinstalado — lo más probable es que sirva tal cual.

**Decisión:**
- OS = Raspberry Pi OS Bookworm+ 64-bit (aarch64) → **saltear Task 2**, seguir con Task 3.
- Otro OS, 32-bit, o SSH imposible → hacer Task 2.

- [ ] **Step 3: Crear alias SSH en el mini-PC**

Agregar a `~/.ssh/config` (crear si no existe):

```text
Host r2130
    HostName <R2130_IP>
    User lucas
```

```bash
ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519 -N "" 2>/dev/null || true   # solo si no hay clave
ssh-copy-id r2130
ssh r2130 'hostname && whoami'
```

Expected: imprime el hostname y `lucas` sin pedir password.

### Task 2: (Condicional) Flashear Raspberry Pi OS Lite 64-bit

Solo si la Task 1 encontró un OS inservible. Si no, saltear.

- [ ] **Step 1: Preparar el flasheo**

La R2130 bootea del SSD NVMe interno. Dos opciones:

- **A (recomendada):** abrir la R2130, sacar el SSD NVMe, conectarlo al mini-PC con un adaptador NVMe-USB.
- **B:** si no hay adaptador, usar una microSD como puente (flashear la SD, bootear de SD, y desde ahí flashear el NVMe con `rpi-imager` en la propia R2130).

```bash
sudo apt install -y rpi-imager
rpi-imager
```

- [ ] **Step 2: Flashear con configuración headless**

En Raspberry Pi Imager:
1. Device: **Raspberry Pi 5** → OS: **Raspberry Pi OS Lite (64-bit)** → Storage: el SSD.
2. En "Edit Settings" (⚙): hostname `r2130`, usuario `lucas` + password, WiFi NO (usará Ethernet), habilitar **SSH con clave pública** (pegar el contenido de `~/.ssh/id_ed25519.pub` del mini-PC), timezone `America/Argentina/Buenos_Aires`.
3. Escribir y verificar.

- [ ] **Step 3: Reinstalar el SSD, bootear y verificar**

```bash
ssh r2130 'cat /etc/os-release | head -2 && uname -m'
```

Expected: `Raspberry Pi OS` / `bookworm`, `aarch64`.

### Task 6: Mosquitto (broker MQTT)

**Files:**
- Create: `docker-compose.yml`
- Create: `mosquitto/config/mosquitto.conf`
- Create: `.env.example`

- [ ] **Step 1: Crear `docker-compose.yml` con el servicio mosquitto**

```yaml
name: home-automation

services:
  mosquitto:
    image: eclipse-mosquitto:2
    container_name: mosquitto
    restart: unless-stopped
    ports:
      - "1883:1883"
    volumes:
      - ./mosquitto/config:/mosquitto/config
      - ./mosquitto/data:/mosquitto/data
      - ./mosquitto/log:/mosquitto/log
    environment:
      - TZ=${TZ}
```

- [ ] **Step 2: Crear `mosquitto/config/mosquitto.conf`**

```text
listener 1883
persistence true
persistence_location /mosquitto/data/
log_dest file /mosquitto/log/mosquitto.log
log_dest stdout
allow_anonymous false
password_file /mosquitto/config/passwd
```

- [ ] **Step 3: Crear `.env.example`**

```text
TZ=America/Argentina/Buenos_Aires
# MQTT (los valores reales van en .env, que NO se commitea)
MQTT_USER=ha
MQTT_PASSWORD=cambiame
```

- [ ] **Step 4: Commit y push (mini-PC), pull en la R2130**

```bash
git add docker-compose.yml mosquitto/config/mosquitto.conf .env.example
git commit -m "feat: compose inicial con mosquitto"
git push
ssh r2130 'cd /opt/home-automation && git pull'
```

- [ ] **Step 5: Crear `.env` y el archivo de passwords en la R2130 (fuera de git)**

```bash
ssh r2130 'cd /opt/home-automation && cp .env.example .env && sed -i "s/cambiame/$(openssl rand -hex 16)/" .env && grep MQTT_PASSWORD .env'
ssh r2130 'cd /opt/home-automation && source .env && touch mosquitto/config/passwd && docker run --rm -v /opt/home-automation/mosquitto/config:/cfg eclipse-mosquitto:2 mosquitto_passwd -b /cfg/passwd "$MQTT_USER" "$MQTT_PASSWORD"'
```

Expected: `grep` muestra la password generada (anotarla mentalmente para la Task 7, o volver a mirarla con el mismo grep).

- [ ] **Step 6: Levantar y verificar pub/sub**

```bash
ssh r2130 'cd /opt/home-automation && docker compose up -d mosquitto && sleep 3 && docker compose ps mosquitto'
ssh r2130 'cd /opt/home-automation && source .env && docker exec mosquitto sh -c "mosquitto_sub -u $MQTT_USER -P $MQTT_PASSWORD -t test -C 1 -W 5 & sleep 1; mosquitto_pub -u $MQTT_USER -P $MQTT_PASSWORD -t test -m hola; wait"'
```

Expected: `ps` muestra `running`; el segundo comando imprime `hola`. Verificar también que el anónimo es rechazado:

```bash
ssh r2130 'docker exec mosquitto mosquitto_pub -t test -m x; echo "exit=$?"'
```

Expected: `Connection error: Connection Refused: not authorised.` y `exit=1`.

### Task 7: Home Assistant

**Files:**
- Modify: `docker-compose.yml`
- Create: `homeassistant/configuration.yaml`

- [ ] **Step 1: Agregar el servicio homeassistant al compose**

Agregar a `docker-compose.yml` (debajo de `mosquitto`, mismo nivel de indentación):

```yaml
  homeassistant:
    image: ghcr.io/home-assistant/home-assistant:stable
    container_name: homeassistant
    restart: unless-stopped
    network_mode: host
    volumes:
      - ./homeassistant:/config
      - /etc/localtime:/etc/localtime:ro
    environment:
      - TZ=${TZ}
    depends_on:
      - mosquitto
```

`network_mode: host` es necesario para descubrimiento (mDNS/SSDP) de la TV y otros dispositivos.

- [ ] **Step 2: Crear `homeassistant/configuration.yaml`**

```yaml
# Config base — Home Assistant genera el resto en .storage/ (fuera de git)
default_config:

homeassistant:
  name: Depto
  time_zone: America/Argentina/Buenos_Aires
  unit_system: metric
  currency: ARS
  country: AR

automation: !include automations.yaml
script: !include scripts.yaml
scene: !include scenes.yaml
```

Crear también los includes vacíos:

```bash
echo '[]' > homeassistant/automations.yaml
echo '{}' > homeassistant/scripts.yaml
echo '[]' > homeassistant/scenes.yaml
```

- [ ] **Step 3: Commit, push, pull y levantar**

```bash
git add docker-compose.yml homeassistant/
git commit -m "feat: servicio homeassistant con config base"
git push
ssh r2130 'cd /opt/home-automation && git pull && docker compose up -d && sleep 30 && docker compose ps'
```

Expected: `mosquitto` y `homeassistant` en estado `running`.

### Task 8: Integración LG OLED C5 (webOS)

**Files:** ninguno (integración por UI; el estado queda en `.storage/`, fuera de git).

- [ ] **Step 1: Preparar la TV**

En la LG C5, con la TV en la misma red que la R2130 (idealmente Ethernet o al menos WiFi del mismo router):
1. Settings → General → Devices → External Devices → activar **"TV On with Mobile"** (encendido por red / network standby).

- [ ] **Step 2: Agregar la integración en HA**

Settings → Devices & Services: la TV debería aparecer **descubierta** ("LG webOS TV"). Si no, Add Integration → **LG webOS TV** → host `<TV_IP>`. En la TV va a aparecer un prompt de autorización → **Aceptar** con el control remoto.

- [ ] **Step 3: Verificar control end-to-end**

En Developer Tools → States: existe `media_player.lg_webos_tv_oled55c5psa` (o similar) con estado `on`/`off` correcto. Probar desde la UI:

1. Con la TV encendida: bajar/subir volumen y mutear desde la tarjeta del media player. Expected: la TV responde.
2. Apagar desde HA. Expected: la TV se apaga.
3. **Encender desde HA** (usa Wake-on-LAN automático de la integración). Expected: la TV enciende. Si no enciende: verificar que "TV On with Mobile" quedó activo y que la TV está por cable; si sigue fallando, agregar fallback WoL:

```yaml
# homeassistant/scripts.yaml — solo si el encendido nativo falla
tv_on:
  alias: "Encender TV (WoL fallback)"
  sequence:
    - action: wake_on_lan.send_magic_packet
      data:
        mac: "<MAC_DE_LA_TV>"
```

(y en `configuration.yaml` agregar la línea `wake_on_lan:`). Commit solo si hizo falta el fallback.

### Task 10: Backup nocturno + runbook

**Files:**
- Create: `scripts/backup.sh`
- Create: `docs/runbooks/instalacion-r2130.md`

- [ ] **Step 1: Crear `scripts/backup.sh`**

```bash
#!/usr/bin/env bash
# Backup nocturno de configs (no media) a /opt/backups. Retiene 14.
set -euo pipefail

BACKUP_DIR=/opt/backups/home-automation
SRC=/opt/home-automation
mkdir -p "$BACKUP_DIR"

tar -czf "$BACKUP_DIR/config-$(date +%F).tar.gz" \
    --exclude='frigate/media' \
    --exclude='homeassistant/home-assistant_v2.db-wal' \
    --exclude='homeassistant/home-assistant_v2.db-shm' \
    -C "$(dirname "$SRC")" "$(basename "$SRC")"

ls -1t "$BACKUP_DIR"/config-*.tar.gz | tail -n +15 | xargs -r rm --
```

- [ ] **Step 2: Probarlo en la R2130 y programarlo**

```bash
chmod +x scripts/backup.sh
git add scripts/backup.sh && git commit -m "feat: backup nocturno de configs" && git push
ssh r2130 'cd /opt/home-automation && git pull && sudo ./scripts/backup.sh && ls -lh /opt/backups/home-automation/'
ssh r2130 '(sudo crontab -l 2>/dev/null | grep -v backup.sh; echo "30 4 * * * /opt/home-automation/scripts/backup.sh") | sudo crontab -'
ssh r2130 'sudo crontab -l | grep backup'
```

Expected: aparece `config-2026-XX-XX.tar.gz` (>1 KB) y la línea de cron `30 4 * * *`.

- [ ] **Step 3: Escribir el runbook de instalación/recovery**

Crear `docs/runbooks/instalacion-r2130.md`:

```markdown
# Runbook: R2130 — instalación y recovery

## Acceso
- `ssh r2130` desde el mini-PC (alias en ~/.ssh/config, IP reservada en el router).
- Servicios: HA en http://r2130:8123, MQTT en r2130:1883.

## Recovery desde cero
1. Flashear Raspberry Pi OS Lite 64-bit al NVMe (usuario `lucas`, SSH por clave,
   hostname `r2130`, TZ America/Argentina/Buenos_Aires).
2. `curl -fsSL https://get.docker.com | sudo sh && sudo usermod -aG docker lucas`
3. Restaurar deploy key de GitHub (o generar y re-autorizar una nueva).
4. `sudo mkdir -p /opt/home-automation && sudo chown lucas: /opt/home-automation`
   `git clone git@github.com:Ltaverna/home-automation.git /opt/home-automation`
5. Restaurar del último backup (tiene .env, mosquitto/config/passwd y
   homeassistant/.storage): `sudo tar -xzf config-<fecha>.tar.gz -C /opt`
   (o recrear .env desde .env.example + passwd con mosquitto_passwd si no hay backup).
6. `cd /opt/home-automation && docker compose up -d`
7. Re-agregar el cron de backup: `30 4 * * * /opt/home-automation/scripts/backup.sh`

## Backups
- Nocturno 04:30 → /opt/backups/home-automation/ (14 días de retención).
- Las configs también están en git; .env/.storage/passwd SOLO en el backup.
```
